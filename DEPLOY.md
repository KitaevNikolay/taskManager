# Деплой обновлений без потери данных

Как обновить приложение на сервере так, чтобы сохранились задачи, сотрудники, отсутствия, заметки, алерты, пользователи и подписки на оповещения.

## Где лежат данные

Всё, что нельзя потерять, хранится вне git, поэтому `git pull` эти файлы не трогает:

| Что | Где | Зачем |
|---|---|---|
| База | `data/app.db` (+ служебные `app.db-wal`, `app.db-shm`) | Все данные приложения, пользователи и пароли, ключи push-оповещений |
| Настройки | `.env` | Вебхук Битрикс24, адрес сайта, почта |
| Бэкапы | `backup/` | Копии базы |
| Выгрузка заметок | `data/vault/` (или путь из `VAULT_DIR`) | Markdown для Obsidian. Пересобирается из базы, поэтому в бэкап не нужна |

В Docker папки `data/` и `backup/` подключены к контейнеру как тома (`docker-compose.yml`). Поэтому пересборка или удаление контейнера базу не стирает, пока вы не удаляете эти папки на сервере. Папка выгрузки по умолчанию лежит внутри `data/` и тоже сохраняется.

Задачи из Битрикс24 приложение перечитывает само. Невосстановимо теряется только то, что живёт лишь в базе: пользователи, отделы, сотрудники, очереди, отсутствия, заметки, история алертов и настройки.

## Главные правила

1. **Перед каждым обновлением делайте бэкап.** Изменения схемы базы применяются автоматически при запуске и обратно не откатываются.
2. **Не копируйте `app.db` обычным `cp` при работающем сервере:** копия может оказаться битой (часть данных лежит в `app.db-wal`). Используйте `npm run backup`: он делает целостную копию прямо на работающем сервере.
3. **Держите копию бэкапа не только на сервере:** скачайте её себе или в другое хранилище.
4. **Не запускайте две копии приложения с одним вебхуком,** например старую локальную и новую на сервере. Они будут независимо опрашивать Битрикс, и данные разойдутся.
5. **Не удаляйте `data/` и не делайте `git clean -fdx`.** Эта команда сотрёт неотслеживаемые папки, в том числе базу и бэкапы.

## План обновления

Команды ниже — для папки `/opt/taskManager`. Если приложение у вас в другом месте, подставьте свой путь. Шаги с пометками **Docker** и **systemd** выполняйте только для своего способа запуска.

### 1. Проверить, что на сервере нет своих правок

```bash
cd /opt/taskManager
git status
git log --oneline -1        # запишите текущий коммит — к нему можно откатиться
```

В `git status` не должно быть изменённых файлов кода. `data/`, `backup/` и `.env` git игнорирует, их там не будет. Если правки есть, сохраните их (`git stash`) или перенесите в репозиторий, иначе `git pull` не пройдёт.

### 2. Сделать бэкап

**systemd / обычный запуск:**
```bash
npm run backup
```

**Docker:**
```bash
docker compose exec app npx tsx server/backup.ts /app/backup
```

Команда напишет путь к файлу (`backup/app-ГГГГММДД-ЧЧММ.db`), `Проверка целостности: ok` и сколько в копии пользователей, сотрудников и задач. Если целостность не `ok`, остановитесь и не обновляйтесь.

Скачайте бэкап себе (команда для вашего компьютера):
```bash
scp user@server:/opt/taskManager/backup/app-ГГГГММДД-ЧЧММ.db ./
```

Сохраните также копию `.env`, если её нет в надёжном месте.

### 3. Получить новую версию

```bash
git pull
git log --oneline -3        # убедиться, что пришёл нужный коммит
```

### 4. Собрать и перезапустить

**Docker:**
```bash
docker compose up -d --build
```
Контейнер пересоберётся и запустится с той же папкой `data/`.

**systemd:**
```bash
npm ci
npm run build
sudo systemctl restart task-manager
```

Перерыв в работе — несколько секунд. Синхронизация с Битриксом продолжится с того места, где остановилась.

### 5. Проверить, что данные на месте

Посмотрите лог запуска.

Docker:
```bash
docker compose logs --tail=50 app
```
systemd:
```bash
journalctl -u task-manager -n 50
```

В логе должна быть строка `Сервер: http://…` и не должно быть ошибок. Строка «Пользователей нет…» после обновления означает, что приложение открыло не ту базу: проверьте `DB_PATH` в `.env` и подключение папки `data/`.

Затем откройте сайт и проверьте:
- вход под своим логином работает;
- в «Кабинете» есть ваши отделы, сотрудники на месте;
- на канбане есть задачи, в «Отсутствиях» и «Заметках» — ваши записи;
- число непрочитанных алертов не выросло скачком: старые алерты не должны прийти заново.

Что проверить для конкретного обновления, написано в разделе «Особенности обновлений» ниже.

Можно проверить и прямо в базе. Docker:
```bash
docker compose exec app node -e "const {DatabaseSync}=require('node:sqlite');const db=new DatabaseSync('/app/data/app.db',{readOnly:true});for(const t of ['users','departments','employees','absences','notes','alerts'])console.log(t,db.prepare('SELECT COUNT(*) n FROM '+t).get().n);console.log(db.prepare('SELECT id,login,role FROM users').all())"
```
Без Docker — та же команда через `node -e "…"` с путём `./data/app.db`.

### 6. Если что-то пошло не так — откат

1. Остановите приложение. Docker: `docker compose down`. systemd: `sudo systemctl stop task-manager`.
2. Отложите текущую базу и верните бэкап:
   ```bash
   mkdir -p backup/failed
   mv data/app.db* backup/failed/
   cp backup/app-ГГГГММДД-ЧЧММ.db data/app.db
   ```
3. Верните код на коммит из шага 1:
   ```bash
   git checkout <коммит-из-шага-1>
   ```
4. Соберите и запустите, как в шаге 4.
5. Когда причина найдена и исправлена, вернитесь на актуальную версию (`git checkout main && git pull`) и повторите план с шага 2.

Старую версию нужно запускать именно со старым бэкапом: новая схема базы старому коду не подходит.

## Особенности обновлений

Разделы идут от новых к старым. Если сервер отстал на несколько версий, прочитайте все разделы новее его текущего коммита.

### Заметки 2.0 и название «Стасик»

Коммит для отката к предыдущей версии: `5f7de6f`.

Что меняется:
- **Связи в заметках.** В заметке можно упомянуть задачу (`#`), сотрудника (`@`) и другую заметку (`[[`). У задачи появляется блок «Заметки», на канбане и у сотрудников — метка 📝. Добавлены вид «Граф», заметка дня («Сегодня») и шаблоны.
- **Поиск по заметкам** теперь полнотекстовый (SQLite FTS5).
- **Выгрузка в Obsidian:** архив `.zip` или автоматическая выгрузка в папку на сервере. Включает каждый пользователь сам на странице «Заметки» → «Obsidian». Пока никто её не включил, на диск ничего не пишется.
- **Название сервиса** везде заменено на «Стасик»: шапка с логотипом, вкладка браузера, экран входа, push-оповещения, тема письма восстановления пароля.

Что произойдёт с базой при первом запуске:
- появятся таблица связей `note_links`, колонка `notes.daily_on` и поисковый индекс `notes_fts`;
- индекс сразу заполнится существующими заметками, на это уйдут секунды;
- упоминаний в старых заметках нет, поэтому связи появятся по мере того, как в заметки будут добавлять `#`, `@` и `[[`.

Изменения только добавляют таблицы и колонку, существующие данные не меняются. Всё равно сделайте бэкап по шагу 2: откат описан для пары «старый код + старый бэкап».

Зависимости и настройки:
- Добавились пакеты, в том числе `turndown` для перевода заметок в Markdown. `npm ci` (systemd) и пересборка образа (Docker) поставят их сами.
- Новая необязательная переменная `VAULT_DIR`: куда выгружать заметки. По умолчанию это `./data/vault`, в Docker — `/app/data/vault`, внутри уже подключённого тома. Если укажете путь вне `data/`, в Docker подключите его отдельным томом в `docker-compose.yml`.
- Процесс приложения должен иметь право писать в эту папку. При пути по умолчанию права уже есть: в `data/` он пишет базу.
- В `deploy/task-manager.service` поменялось только описание (`Description`). Если вы копировали этот файл в `/etc/systemd/system/`, обновлять его не обязательно.

После обновления дополнительно проверьте:
- в «Заметках» поиск находит заметку по слову из текста без учёта регистра;
- в новой заметке ввод `#` и номера задачи открывает список задач, а после сохранения задача показывает эту заметку в блоке «Заметки»;
- кнопка «Сегодня» создаёт заметку дня в табе «Дневник»;
- «Obsidian» → «Скачать архив .zip» отдаёт архив с папками табов.

Подключение папки выгрузки к Obsidian (по желанию):
- папка пользователя — `data/vault/<логин>/`, в ней `.taskmanager.json` со списком выгруженных файлов: выгрузка удаляет только их и не трогает файлы, добавленные вручную;
- доставить папку на компьютер можно через Syncthing (обычные файлы, работает в фоне) или через WebDAV в nginx с паролем и плагином Remotely Save в Obsidian (подходит и для телефона);
- выгрузка односторонняя: правки, сделанные в Obsidian, в кабинет не вернутся и перезапишутся при следующей выгрузке. Правьте заметки в кабинете.

### Многопользовательская версия (коммит `86a23a2`)

Это обновление переводит базу на схему с пользователями и отделами. Если на сервере сейчас версия старше `86a23a2`, при первом запуске произойдёт следующее:

- Все существующие данные перейдут **первому созданному пользователю** — с наименьшим ID — и он станет администратором. Перед обновлением проверьте, кто это:
  ```bash
  # Docker
  docker compose exec app node -e "const {DatabaseSync}=require('node:sqlite');console.log(new DatabaseSync('/app/data/app.db',{readOnly:true}).prepare('SELECT id,login FROM users ORDER BY id').all())"
  ```
  Первым в списке должны быть вы.
- Группа из `BITRIX_GROUP` в `.env` станет вашим первым отделом. После обновления эта переменная больше не нужна, но и не мешает.
- Подписки на оповещения в браузере, история алертов и личные пороги сохранятся.

Коммит для отката к версии до этого обновления: `3e3ea25`.

## Регулярные бэкапы

Чтобы не зависеть от ручных бэкапов, добавьте ежедневный бэкап в cron (`crontab -e`).

Docker:
```
0 3 * * * cd /opt/taskManager && docker compose exec -T app npx tsx server/backup.ts /app/backup >> backup/backup.log 2>&1
```
systemd / обычный запуск:
```
0 3 * * * cd /opt/taskManager && npm run backup >> backup/backup.log 2>&1
```

Старые копии можно удалять, например оставлять последние 14:
```
30 3 * * * cd /opt/taskManager/backup && ls -1t app-*.db | tail -n +15 | xargs -r rm --
```

В бэкапах лежат хэши паролей и все данные, поэтому храните их в закрытом месте.
