# Задачи отдела — админка поверх Битрикс24

Канбан группы отдела, очереди сотрудников, Гант с зависимостями и алерты. Данные синхронизируются с Битрикс24 через входящий вебхук.

## Запуск

```bash
npm install
npm run build      # собрать фронт
npm start          # http://localhost:3001
```

Разработка: `npm run dev`. Сервер работает на :3001, фронт — на http://localhost:5173 (проксирует `/api`).

Docker: `docker compose up -d --build`. База лежит в `./data`.

## Настройка (.env)

| Переменная | Назначение |
|---|---|
| `BITRIX_TASK_WEBHOOK` | Входящий вебхук. Обязательные скоупы: `task`, `tasks`. Желательно добавить `user` и `department` — без них по кнопке «Заполнить из Б24» подтягиваются только ФИО и должность |
| `BITRIX_GROUP` | ID группы отдела (канбан строится по её стадиям) |
| `APP_URL` | Адрес приложения для ссылок в письмах (по умолчанию `http://localhost:PORT`) |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` | Почта для восстановления пароля |
| `PORT`, `DB_PATH` | Порт и путь к SQLite |

## Вход

- При первом запуске сайт предложит создать администратора (логин, имя, почта, пароль). Остальные пользователи добавляются в «Настройки → Пользователи».
- «Забыли пароль?» отправляет на почту одноразовую ссылку (действует 1 час); при сбросе пароля завершаются все сеансы пользователя.
- Без настроенного SMTP ссылку для сброса выдаёт команда на сервере: `npm run reset-password -- <логин>`.
- Пароли хранятся как хэш scrypt; после 5 неудачных попыток вход по логину блокируется на 5 минут.

## Разделы

- **Сотрудники** — ID в Б24, ФИО, отдел, почта, должность. Кнопка «Заполнить из Б24» подставляет данные по ID.
- **Канбан** — задачи группы по стадиям канбана Б24. Перетаскивание между колонками меняет стадию, перетаскивание на сотрудника в правой панели назначает ответственного. В режиме сотрудника показаны все его задачи (в том числе вне группы), колонки — статусы; перетаскивание меняет статус.
- **Очереди** — открытые задачи каждого сотрудника в порядке приоритета (порядок задаётся перетаскиванием и хранится локально). Подсказка «нет задачи в работе — следующая…», назначение из бэклога. «Цепочка в Гант» ставит задачи очереди друг за другом по рабочим дням и записывает плановые даты и связи «окончание → начало» в Б24.
- **Гант** — плановые даты (`START_DATE_PLAN`/`END_DATE_PLAN`), крайние сроки, зависимости. Бары можно двигать и растягивать, связи создаются в режиме «Связать задачи». Красным подсвечиваются нарушенные связи и планы, выходящие за крайний срок.
- **Алерты** — изменения в задачах (по истории Б24, с автором), новые комментарии, назначения, задачи, долго висящие на сотруднике, задачи без движения, приближающиеся и просроченные сроки. Новые события приходят в браузер сразу (SSE и уведомления браузера). Пороги настраиваются в разделе «Настройки».

## Оповещения в браузере

Включаются в «Настройки → Оповещения в браузере» (или кнопкой 🔔 в шапке). Используется Web Push: оповещения приходят и при закрытой вкладке, пока браузер запущен. Ключи VAPID создаются автоматически и хранятся в базе.

- Можно выбрать, по каким типам алертов присылать оповещения и по каким задачам: по всем или только по задачам выбранных сотрудников.
- В карточке задачи есть переключатель «По правилам / Всегда / Никогда» — он важнее общих правил.
- Если за один цикл синхронизации набралось 4 и больше алертов, приходит одно сводное оповещение.
- Push работает на `localhost` или по HTTPS. При доступе по IP или домену без HTTPS браузер подписку не даст.

## Как устроена синхронизация

- Каждые 30 сек (настраивается) сервер забирает задачи группы и задачи сотрудников, изменённые с прошлого опроса (`>CHANGED_DATE`, `>ACTIVITY_DATE`). Раз в 10 минут проходит полная сверка: открытые задачи плюс закрытые за 30 дней, удалённые и выпавшие из области задачи убираются из базы.
- По изменённым задачам через `batch` подтягиваются история (`tasks.task.history.list`) и зависимости. Из истории вычисляется, с какого момента задача на текущем ответственном и в текущей стадии.
- Действия из админки выполняются от пользователя вебхука и в алерты не попадают.
- Комментарии в новых задачах Б24 хранятся в чатах, а без скоупа `im` их текст недоступен. Поэтому новый комментарий определяется по сдвигу `ACTIVITY_DATE` без изменения полей задачи.
- Порядок очередей хранится в локальной базе (в Б24 нет аналога).
